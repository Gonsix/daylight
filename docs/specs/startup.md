# Daylightの起動時の動作

この文書は、Daylight 0.3.7の現在の実装における、Obsidian起動時の動作をまとめたものです。主な実装は `src/main.tsx`、`src/store.ts`、`src/Daylight.tsx` にあります。

## 起動から画面表示まで

1. **プラグインの登録**：ObsidianがDaylightを読み込むと、保存済み設定を読み込み、データストア、専用ビュー、リボンアイコン、コマンド、Markdownコードブロックの処理を登録します。ストアの準備状態は最初は未完了です。ビューはワークスペースの復元に備えて、データ準備より先に登録します。
2. **ワークスペースの準備を待つ**：Obsidianの `onLayoutReady` が呼ばれた後、Daylightの保存フォルダとテンプレートを確認します。存在しないものは作成し、既存のテンプレートは上書きしません。初期化に失敗した場合は通知とコンソールへのエラー出力を行い、後続の起動処理を続けます。
3. **メタデータを確認する**：DaylightのTasks、Events、Projectsフォルダ以下のMarkdownファイルを列挙し、Obsidianのメタデータキャッシュが存在するか確認します。すべて存在すればすぐ次へ進みます。存在しないものがあれば、メタデータの `resolved` イベントまたは3秒のタイムアウトのうち、先に発生した方を待ちます。イベント後やタイムアウト後に、全ファイルのキャッシュが揃ったかどうかは再確認しません。
4. **設定に応じて専用タブを開く**：「起動時にDaylightを開く」がオンの場合、既存のDaylightタブがあればそれを表示し、なければ新しいタブを作成します。オフが既定値です。オフでも、Obsidianによるワークスペース復元や、ユーザーによる操作でビューが開かれることはあります。起動時に開く処理が失敗した場合は通知し、後続の準備完了処理を続けます。
5. **ストアを準備完了にする**：上記の処理の後、`requestAnimationFrame` を2回待ってからストアを準備完了にし、購読中の画面に通知します。同APIがない環境ではすぐに完了にします。
6. **画面を描画して表示する**：準備完了前にDaylightビューや埋め込みが開かれた場合、その領域に「読み込み中…」を表示します。準備完了後はダッシュボードを非表示状態で描画し、その上にローディングを重ねます。さらにその画面のウィンドウで `requestAnimationFrame` を2回待ってから、ローディングを外してダッシュボードを表示します。操作とアクセシビリティツリーへの露出は、表示されるまで抑止します。

新しい専用タブを自動で開く場合、タブの作成は上記3の後です。そのため、メタデータ待ちの間から必ずDaylightのローディング画面が見えるわけではありません。既に復元されたビューや埋め込みでは、ストアの準備中から表示できます。

## 起動時のデータと日付

専用ビューは端末のローカル時刻に基づく当日を初期表示し、タスクの「今日」タブを選択します。日付が指定されたMarkdown埋め込みでは、指定日を初期表示します。コードブロックの日付指定がない場合は、所定のデイリーノートのパスから日付を読み取り、該当しなければ当日を使用します。

初期表示時に、当日分のファイルだけを取得する実装ではありません。`store.items()` は対象フォルダのMarkdownファイルを列挙し、Obsidianのキャッシュからメタデータを読み取ってアイテムを構築します。frontmatterがなく、種類を判定できないファイルは表示対象になりません。その後、画面側で日付などを使って絞り込みます。

「今日」タブには、当日を予定日とするタスク、当日に予定または作業実績が重なるタスク、過去からの未着手・進行中の繰り越しタスク、当日に完了したタスクが含まれます。タイムラインには当日に重なる予定や作業実績を表示します。プロジェクト欄には日付に関係なく、アーカイブされていない有効なプロジェクトを表示します。したがって、画面全体が厳密に当日の日付を持つデータだけに限定されるわけではありません。

## 描画後の調整と更新

タイムラインは表示領域の大きさを監視し、寸法が取れるようになった時点で初期スクロール位置を調整します。当日なら現在時刻を中心付近に、別の日なら最初の予定付近、予定がなければ9時付近に移動します。非表示のタブなどで寸法が取れない場合は、取れるまで待ちます。

2フレームの待機は描画後の調整を待つための措置ですが、タイムラインの寸法取得やスクロール調整の完了自体を確認してからローディングを外す仕組みではありません。また、3秒のタイムアウト等によりメタデータが未完成のまま表示を開始する場合があります。後からメタデータやファイルが更新されるとキャッシュを無効化し、画面を更新します。時刻表示も30秒ごとに更新します。

## 表示範囲と障害時

ローディング画面が覆うのはDaylightの専用ビューまたはノートへの埋め込み領域です。Obsidian全体、ワークスペース復元中の画面、他のプラグインのツールバーは覆いません。DaylightのReact描画中にエラーが発生した場合は、ビューを開き直すよう促すエラーを表示し、詳細をコンソールに出力します。
