# 多言語対応

## 利用者向けの動作

Daylightの設定のLanguage（言語）から以下の9言語を選択する。既定は英語で、保存済み設定にlanguageがない場合や不明な値の場合も英語を使う。選択はプラグイン設定の `language` に保存する。保存成功後に開いているReact画面やモーダルの表示、設定画面とコマンド名を更新する。言語設定の保存が失敗した場合は元の選択を保つ。

| 言語 | 設定の表示名 | 保存コード | 日付のロケール |
| --- | --- | --- | --- |
| 英語 | English | `en` | `en-US` |
| 日本語 | 日本語 | `ja` | `ja-JP` |
| 中国語・簡体字 | 简体中文 | `zh-CN` | `zh-CN` |
| 韓国語 | 한국어 | `ko` | `ko-KR` |
| 中国語・繁体字 | 繁體中文 | `zh-TW` | `zh-TW` |
| スペイン語 | Español | `es` | `es-ES` |
| ドイツ語 | Deutsch | `de` | `de-DE` |
| フランス語 | Français | `fr` | `fr-FR` |
| ポルトガル語・ブラジル | Português (Brasil) | `pt-BR` | `pt-BR` |

翻訳対象はダッシュボード、カンバン、日付選択、作成・編集・削除画面、プロパティ名、設定、通知、検証エラー、操作ラベル。日付と曜日の表示にも選択言語のロケールを使う。ユーザーが入力したタイトル、プロパティ名、メモやObsidian自体が返すエラー等は翻訳しない。既に発生して画面に保持されているエラー文は、次の操作まで発生時の言語が残る場合がある。

## 保存データ

言語変更はノートの本文、frontmatterのキーや状態値、ファイル名、保存先、テンプレートを変換しない。既存テンプレートの日本語見出しもそのまま扱う。ノート作成・編集に使う保存形式は全言語で共通で、表示用の翻訳は保存内容に使用しない。

## 翻訳の構成

- `src/locales/ja.json`: 既存の日本語を登録した辞書。日本語の原文と番号付きプレースホルダーをメッセージの識別子として使う。
- `src/locales/en.json`: 同じ識別子に対応する英語。
- `src/locales/zh-CN.json`: 中国語（簡体字）。日付表示には `zh-CN` を使用する。
- `src/locales/ko.json`: 韓国語。日付表示には `ko-KR` を使用する。
- `src/locales/zh-TW.json`: 中国語（繁体字）。「資料夾」「儲存」「專案」などの表現を使用する。
- `src/locales/es.json`: スペイン語。
- `src/locales/de.json`: ドイツ語。
- `src/locales/fr.json`: フランス語。
- `src/locales/pt-BR.json`: ポルトガル語（ブラジル）。
- `src/i18n.ts`: 対応言語、ロケール、辞書の型検証、補間、変更通知を管理する。React画面は `useLanguage()` で変更を購読する。

各辞書には254項目を登録する。翻訳文ではプレースホルダーの順番を変えられる。

`{0}` 等は実行時の値で置換する。タイトル等の補間値をさらに翻訳したり、翻訳結果をHTMLとして解釈したりしない。翻訳済みの状態名やプロパティ名は保存用の識別子と区別し、表示時に評価する。

## 言語を追加する場合

1. 日本語辞書と同じキーを持つ新しい辞書を作る。すべてのプレースホルダーを保つ。
2. `LANGUAGE_INFO` にコード、言語名の自称、Intlで使用するロケールを追加する。
3. 辞書を `messages` に登録する。設定の選択肢は登録情報から生成される。
4. 辞書のキー・プレースホルダーの一致、画面の描画、設定の保存・復元とノートの保存形式を検証する。

中国語の簡体字と繁体字は別の辞書として管理する。将来の言語追加時にも保存データの移行は不要。

## 検証

`tests/i18n.test.ts` は既定言語、辞書の対応、補間、変更通知、状態・プロパティ名の切り替え、保存内容が言語に依存しないことを確認する。`tests/render.test.ts` は日本語以外の全対応言語のダッシュボード・作成・予定・削除フォームの固定文言と日本語への復帰を確認する。`tests/plugin.test.ts` は設定の保存・復元、表示更新、保存失敗時の復元を確認する。
