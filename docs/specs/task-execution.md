# タスクの状態と作業実績

## 保存形式

作業の予定時刻 `schedule_start` / `schedule_end` と実績は別に管理する。実績は `task_sessions` の文字列リストに `開始..終了` として保存し、実行中の最終セッションは終了を空にする。`task_start` は最初の開始、`task_end` は最後の終了または空となる。日時はローカル時刻の `YYYY-MM-DDTHH:mm:ss`。旧形式の開始・終了フィールドからもセッションを解釈する。

```yaml
status: on_going
task_start: 2026-11-13T09:00:00
task_end:
task_sessions:
  - '2026-11-13T09:00:00..2026-11-13T09:30:00'
  - '2026-11-13T10:00:00..'
```

## 操作と状態遷移

| 操作・遷移 | 実績と状態 |
| --- | --- |
| 開始・再開 | `on_going` にし、開いたセッションがなければ現在時刻から追加する。複数タスクの並列実行が可能。 |
| 一時停止 | 実行中の最後のセッションを閉じる。状態は `on_going` のまま。 |
| 終了 | 状態を `done` にし、開いているセッションを閉じ、完了日時を記録する。 |
| `on_hold` / `cancelled` / `done` に変更 | 開いたセッションがあれば閉じる。 |
| `todo` に変更 | セッションと実績開始・終了を空にする。 |

未完了から `done` になると `completed at` に現在時刻を記録し、完了を取り消すと空にする。直接完了にした場合も終了時刻を記録するが、不明な開始時刻は推測しない。既に完了していて完了日時がないノートには、遡って日時を作らない。状態変更に伴う作業実績の変更は予定日時を変更しない。

終了済みセッションの長さだけを合算し、秒を切り捨てた時間:分で表示する。進行中セッションは合計に含めず、タイムライン上では現在時刻まで伸ばす。状態とセッションを確認して実行中と判定し、未来の開始時刻に対する終了など不正な操作を拒否する。

開始・停止・終了では最新のノートを処理し、表示時点から状態や実績が変化していれば保存を拒否する。詳細画面でセッションを編集する場合、各要素は `開始..終了` 形式、途中のセッションには終了が必要で、終了は開始以降とする。編集内容に応じて開始・終了フィールドも同期する。
