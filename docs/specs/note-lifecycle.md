# ノートの作成・編集・削除

## 作成とテンプレート

作成時点の `<root>/Templates/` 内のテンプレートを読み、YAML frontmatterと本文を基にノートを作る。対応するTemplater表記はfrontmatter区切りと `tp.file.creation_date("YYYY-MM-DD")` 相当のみで、残った未対応の `<%` 式は実行せずエラーにする。テンプレートに必要なfrontmatterがない場合も作成しない。種別タグと入力値を設定し、その他の属性や本文を引き継ぐ。プロジェクトのゴールは `## ゴール` に追加し、見出しがない場合はエラーにする。作業場所に入力したフォルダは作成しない。

タイトルは前後の空白を取り、空文字、ファイル名に使えない指定文字、末尾のドット、120文字超を拒否する。予定日時は開始・終了必須、1分単位、終了が開始より後。タスク作成時の予定開始・終了は両方空か両方入力し、終了を開始より後とする。予定日と締切は独立し、相互に推測しない。日またぎは可能。

タスクは `タイトル YYYY-MM-DD.md`、予定は `タイトル 開始日.md`、プロジェクトは `タイトル.md`。タスクの予定日が空なら `TBD` を使う。同名の場合は ` 1`、` 2` 等を付けて空きを探し、作成競合が起きた場合も既存ファイルを上書きしない。参照先のプロジェクトや親タスクは存在と種類を確認する。新規タスクは同じ状態の列の末尾の順序を採番する。

## タスクの編集と競合

編集開始時のプロパティをスナップショットとして保持する。保存時は変更した項目それぞれについて現在値と開始時の値を比較し、同じ項目が外部変更されていれば拒否する。変更対象外のプロパティや本文の更新は最新の内容に残す。YAMLの文字列・数値・真偽値・日付・リスト等を扱い、混在リストやオブジェクトはYAMLで編集する。`task` の識別を失う変更は拒否する。

予定日が変わると、タイトルを保ち、日付または `TBD` をファイル名に反映する。同名は連番で回避する。まず内容を保存し、次にObsidianのFileManagerでリネームする。リネームに失敗した場合、その後の別編集がないことを確認できれば内容を元に戻す。復元できない場合は一部保存済みと通知する。

## 予定の編集と削除

予定の編集は、開始時の**ノート全文**をスナップショットとして保存する。保存・削除前に全文を比較し、異なれば拒否する。予定更新は状態、開始・終了、開始日に基づく `target_date`、プロジェクトを更新し、他の属性と本文を維持する。解決できない既存プロジェクトリンクは、変更しない限り保持する。タイトルまたは開始日の変更時はファイル名を同期し、失敗時はタスクと同様に安全な場合だけ内容を戻す。

予定、タスク、プロジェクトの削除は確認画面を経由し、確認開始後に全文が変わっていれば拒否する。種別を検証してObsidianの `trashFile` を使う。プロジェクト削除は所属ノートを連鎖削除しない。

メモ追記は最新の本文に対して行い、`## Notes` 内に日時付きで追加する。見出しがない場合は末尾に作る。frontmatterやコードフェンス内の見出しは対象にせず、他の見出しや本文を残す。

## 書き込みの順序

同一キーの操作はストア内のキューで直列化し、主要な作成・変更・削除・並べ替えは共通の更新キーも使う。これはプラグイン内の操作を調整する仕組みで、外部プラグインや他端末の操作をロックするものではない。外部変更に対しては上記の比較や安全な復元で対処する。

**実装:** `src/store.ts`, `src/create.ts`, `src/event.ts`, `src/task.ts`, `src/model.ts`。**主なテスト:** `tests/store.test.ts`, `tests/task.test.ts`, `tests/event.test.ts`。
